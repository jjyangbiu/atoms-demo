# ADR 0005：迭代轮意图分流与产物核验——ADR 0004 的第 7、8 层

- 状态：已接受（2026-09-15 经需求拷问会逐项裁决通过；实现规格见 `docs/tracker/0021-intent-routing-and-artifact-verification.md`）

## 背景

ADR 0004 叠了六层防线治理"改 A 动了 B"，但两个痛点仍在：

- **A 类·越界改动无自动检测**：六层里第 1–4 层是预防（工具层物理闸），第 6 层是检测（diff 面板）——但检测靠**用户肉眼比对**。系统从不知道"这一轮改的东西超出了用户要求的范围"：`touched_files` 只记录改了哪些文件，从不校验该不该改。
- **B 类·对话被过程信息污染**：`ENGINEER_SYSTEM_PROMPT` 第 7 条约 200 字、`COMPLETION_CLAIM_PATTERNS` 19 个固定短语、`COMPLETION_CLAIM_RES` 四个正则族、三级升级链、收尾无条件追加的核验标注——一整套机器只为判定"模型是不是口头完成"。代码注释自己承认"固定词表穷举不尽实际措辞""宁可偶有误报"：这是在给一个本该确定性的判断打中文措辞补丁。同时每个工具调用落一行 `kind='event'` 并平铺渲染在对话主流里。

根因是**工程师智能体是仓内唯一没有结构化出口的智能体**：澄清智能体唯一出口是 `ask_options`/`start_build`，拆单智能体唯一出口是 `submit_tickets`，都是结构化 JSON 走工具参数 + 服务端 schema 校验 + 非法回喂修正 + `recover_clarify_payload` 兜底恢复。工程师智能体却靠自由文本收尾，于是只能用正则去猜文本里的语义。

## 决策

新增两层，均为 ADR 0004 的**增补而非替代**——0004 的第 1–4、6 层原样保留，第 5 层（迭代日志）字段调整。

### 第 7 层·意图分流（能力边界）

迭代轮（项目已有文件 + 落到工程师智能体的用户对话轮）开始时，先做一次**不绑工具、不流式**的分类调用，输出 `{intent, user_goal, target_files}`：

- `intent=consult` → 绑**只读工具集**（仅 `read_file` + `search_templates`），物理上不含写能力，走流式纯文本收尾，不产生产物也不核验；
- `intent=modify_code` → 绑完整工具集进循环。

沿用澄清智能体"不绑文件工具则物理上无法写代码"的手法：**不靠劝说，靠能力缺失**。枚举只有二值——`question`/`chitchat` 的能力边界与风险画像完全相同，合并为 `consult`；`big_change`/`refactor` 没有可执行的路由后果差异（允许动几个文件由 `target_files` 承载），不设。

分类器**只决定能力边界，不决定义务**：`modify_code` 轮仍可在终结出口自报 `intent=no_change` 合法收尾。因为误判代价不对称——假阳性（问被判改）有轮内自愈机制，假阴性（改被判问）没有——所以**不确定时一律倒向 `modify_code`**；解析失败或枚举越界同样静默降级为 `modify_code`。分类器故障绝不阻断用户轮次。

### 第 8 层·产物核验（声明与事实成对比对）

`modify_code` 轮的唯一合法出口是终结工具 `submit_turn_result`，携 `{intent, summary, changed_files, no_change_reason}`。轮末做两层相互独立的核验：

- **自洽性核验（确定性代码，零成本）**：比对声明的 `changed_files` 与磁盘真实改动的文件集。覆盖三种失配：声明有改动而实际零改动（**口头完成**）、声明零改动而实际有改动（**偷偷改了没说，今天完全测不到**）、文件集不符。这一层单独就取代了整套中文措辞正则机器，且无漏报无误报。
- **正确性裁判（独立 LLM 调用）**：自洽性只证明"模型说了真话"，不证明"它干的是用户要的事"；ADR 0004 把增量修改语义定为**区域级**，而"该不该改这一处"代码判定不了。仅在 `modify_code` 轮且磁盘真有改动时触发。裁判输入是**用户原话 + 最近几轮上下文 + 代码已算好的 diff**（hunk 由 `difflib` 定位并附行号，不让裁判自己数行）；**不得看见智能体的任何自述**（`summary`/`user_goal` 均不给），否则退化为让模型给自己打分。输出 `{verdict: in_scope|out_of_scope|incomplete, out_of_scope_hunks}`。

处置：自洽性失配 → 把"你声明的 vs 磁盘实际的"精确差异回喂一次，仍失配则标注收尾；`out_of_scope` → 列出越界 hunk + **不建快照** + 交用户裁决；`incomplete` → 标注但照建快照（改动合法、只是没做完，不该惩罚）。

**越界轮不建快照**的理由是语义的：版本快照是"某次成功生成后的完整留档、可回滚"，越界改动不该被自动升格为官方认可的正式版本，那会污染回滚列表——这是 0004"零改动轮不建快照，避免制造『版本 N+1』的假进展"同一条理由的延伸。副作用是**无需新增"接受并留档"机制**：快照是全量留档，用户若接受，越界改动自然被下一次成功轮的快照吸收；若选择回滚上一版，恰好就是丢弃这一轮。

**diff 基准必须是磁盘而非快照**：越界轮不建快照会使快照序列与磁盘序列脱钩，故轮前指纹取磁盘状态（`_file_summaries` 本就读磁盘），轮末重算即得真实改动集。

**权威来源归位**：`touched_files` 今天靠解析自己发给前端的 SSE 事件 payload 的 `args.path` 收集（而 `summarize_args` 会截断超 200 字符的参数），却承担着"是否建快照 / 迭代日志记什么 / 是否发 no_change 警告"三重硬闸职责——这是运气不是设计。改为以沙箱与轮前/轮后指纹为权威来源；事件行退回"给人看的过程记录"，不再兼任系统判据。

### 作用域矩阵

爆炸半径控制线：**自洽性核验免费且不需额外上下文，故覆盖所有会写文件的工程师轮次；正确性裁判需 +1 调用且需诉求基准，故只覆盖迭代轮。**

| 轮次 | 分类器 | 只读集 | 终结出口 | 自洽性 | 裁判 | 卡片 | 入日志 |
|---|---|---|---|---|---|---|---|
| 首建轮（无文件） | ✗ | ✗ | ✓ | ✓ | ✗（无旧文件，越界概念不存在） | ✓ | ✓ |
| 迭代·modify_code | ✓ | ✗ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 迭代·consult | ✓ | ✓ | ✗（能力边界决定核验义务：无产物可校验） | ✗ | ✗ | ✗ | ✗ |
| 团队工单执行 | ✗ | ✗ | ✓ | ✓ | ✗（后续可用 `Ticket.deliverable` 作基准） | ✓ | ✗ |

首建轮不进分类器是硬风险规避：首建轮的诉求在分类器眼里很像"用户在描述需求"，一旦判成 `consult` 走只读集，**应用永远建不出来**；而首建轮没有旧文件可越界，A 类风险为零——风险全在，收益全无。确定性阶段分流（`guide`/`exec_guide`/`clarify`/`spec`/`break`）原样保留，不用 LLM 分类器替换状态机。团队工单执行是内部编排而非用户对话轮（0004 已定性），不做意图识别。

### 迭代日志调整

条目按「改动」而非「对话轮」累积，字段 `round`→`seq`、渲染文案「第 N 轮」→「第 N 次改动」（否则 `consult` 轮不入账后编号与对话轮错位，是对模型说谎）；注入内容用分类器蒸馏的 `user_goal`（≤50 字）替代 `user_text[:100]`，但 `user_text` 仍落库（`user_goal` 是模型写的、可能失真，原始诉求才是权威）；新增核验结论字段。`consult` 轮不入账——日志存在的唯一理由是跨对话窗口存活，而近期问答本就在窗口内，**需要跨窗口存活的是改动，不是问答**。

净 token 账：`user_goal`(≤50字) 换掉 `user_text[:100]`、加核验结论几个字，每条持平或更短；`consult` 轮不入账直接砍掉一类膨胀源。故暂不设截断上限，不预先优化。

### 降级铁律

**核验是安全网，安全网故障不得扣住用户的劳动成果，也不得让轮次卡死。** 预防靠 0004 的四层物理闸，它们不依赖任何模型配合。

- 裁判失败（网络/超时/非法 JSON）→ 重试一次（复用 `max_retries` + `RETRY_BACKOFF_SECONDS` 语义），仍失败则标注"核验未完成"、**快照照建**。反方意见（越界会溜过去）由第 6 层 diff 面板与项目级回滚兜底，且"核验未完成"徽标把安全网故障**显式化**而非静默吞掉。
- 模型不调终结出口 → 照 `recover_clarify_payload` 房规从后往前扫描正文里的 JSON 候选起点、失败补 `}` 重试；仍无则回喂一次"你的唯一出口是 `submit_turn_result`"，再不听以该散文作 `summary` 兜底收尾。
- **兜底路径铁律：`changed_files` 一律以磁盘真实值填充，绝不采信模型声明**——兜底恰恰是模型不配合的场景，此时采信自报等于放弃核验。
- `max_steps` 耗尽：维持现状（不建快照、磁盘留脏改动），与"越界轮不建快照"语义天然一致。
- 分类器假阴性（想改被判 `consult`）：不做任何补偿机制——不加提示文案（又一条散文噪音）、不做"我想修改"快捷重发（过度设计）。代价是白跑一轮、零文件损坏，用户下一轮纠正。

### 成本边界

分类器与裁判**都不消耗限流名额**，`charged` 判定保持"一轮对话一个名额"（名额的领域语义是"用户发起一轮生成"，二者是这一轮的内部开销；吃名额会让用户觉得"说一句话被扣三次"）。但成本是真的：有改动的迭代轮从 `1+N` 次调用变为 `1+N+1`。故新增 `llm_utility_model` 配置项，默认等于 `llm_model`；分类器与裁判都是"输入小、输出小、不需要强推理"的任务，是切小模型的完美候选，但**本次不切**，避免引入未验证的第二个模型，留作实测后改一个配置就能切的开关。

### 前端渲染

工具事件仍然落库（`_persist_event` 的既有契约：刷新页面可回看完整过程，且是排查越界改动的证据链），但**默认折叠为一行轮次摘要**（"本轮读取 3 个文件、修改 2 个文件"）可展开看明细。B 类痛点的本质从来不是"这些信息存在"，而是"被平铺在对话主流里"——这是纯渲染层决策，风险最低、可独立回退。`thinking` 今天已默认折叠，不是噪音源。

`modify_code` 轮的 `summary` 只经终结出口这一个通道产出（散文通道关闭），落库为新的结构化 kind（`turn_result`）承载整个 payload，前端渲染成卡片：一句话总结 + 改动文件清单 + 核验结论徽标 + 展开看 diff。这不算引入新的割裂——`_engineer_stream` 今天已经"流结束后 loadHistory 以持久化结果重渲染"，且核验标注只追加到持久化文本、不进入流式输出，**"流式看到的"与"落库回看的"本来就不一致**；此处只是把既有的不一致变成设计意图。

### 实施顺序

先做确定性收益，再做概率性机制；每步可独立验证、可独立回退。

1. **`touched_files` 权威来源重构**（沙箱 + 轮前/轮后指纹）。纯内部重构、零行为变化，但必须最先做——**改动集本身若不可信，自洽性核验与裁判都建在沙上**。
2. **终结出口 + 自洽性核验 + 退役整套中文正则机器 + `turn_result` 卡片 + 迭代日志字段调整**。不引入任何新 LLM 调用，是全部价值的大头；完成后即使 3/4/5 全部回退也已净赚。
3. **分类器 + 只读工具集 + `user_goal` 接入日志**。第一个新调用点。
4. **裁判 + 越界处置**。第二个新调用点，最需观察误判率。
5. **前端工具事件折叠**。纯渲染层。

**裁判处置分两阶段上线**：阶段一只标注不阻断（越界轮照常建快照、卡片把越界 hunk 标红），收集真实误判率；阶段二确认误判率可接受后才启用"不建快照"。裁判是 LLM 而我们手上没有任何误判率数据，一上线就让它决定是否留档版本，其 bug 会静默破坏版本存档链路且用户难以归因（他只看到"版本列表怎么不涨了"）。阶段一让它在**无破坏力**的位置上先证明自己。

## 被否决的替代方案

- **单次结构化调用直接返回编辑指令、取消工具循环**：模型失去按需 `read_file` 的能力，必须前置注入全部文件内容——与 0004 已否决的"扩大窗口代替迭代日志"同类 token 爆炸，且 `max_steps`/沙箱/快照/集成测试全需重写。
- **原生 `response_format` JSON Schema 作为结构化载体**：MiniMax 全系支持的是 **JSON Mode**（`type:"json_object"`），只保证语法合法，不保证字段/类型/枚举合法，服务端校验层无论如何省不掉。更关键的是 **`response_format` 与 tools 是两条互斥的输出通道**：绑了工具还强制 `json_object`，模型往往倾向吐 JSON 而不去调工具，循环直接断掉。故前置分类调用（无工具）用 JSON Mode、循环终结出口（有工具）走工具参数——两者各得其所，不是二选一。另注：MiniMax 推理模型把思考标签块行内混进 content（`ThinkSplitter` 因此存在），JSON Mode 下须先用现成的 `strip_think_blocks` 洗一遍再解析。
- **用分类器声明的 `target_files` 做沙箱硬闸（越界 `edit_file` 直接拒）**：分类器看不到文件内容，只有路径+行数+哈希+迭代日志，猜错就卡死整轮（改个按钮颜色常要同时动 HTML 和 CSS）。故声明范围只用于注入上下文与轮末比对。
- **裁判自动回滚越界 hunk**：把不可逆的破坏性操作建立在概率判断上；且多处改动交织时按 hunk 还原可能产出语法破碎的文件。0004 已以同一理由否决"行级自动回滚过于激进"，不自我翻案。
- **把裁决回喂让模型自动返工**：延迟叠加（一轮可能触发 2–3 次裁判），且模型自纠越界极易引入**新的**越界。
- **`consult` 轮完全不绑工具（零工具纯文本流）**：牺牲真实能力——用户问"按钮颜色在哪个文件定义"，只给路径+行数+哈希答不出内容级问题。改绑只读集：保住回答质量，写能力仍然物理缺失；产生的 `read_file` 事件行属 B 类噪音，**在渲染层解决，不靠砍能力解决**。
- **`question` 与 `chitchat` 分设两个枚举值**：能力边界与风险画像完全相同，分开只增加误判面。
- **增设 `rollback` 意图、由系统直接弹回滚确认框**：让分类器触发破坏性操作，且回滚已有确定性 UI 路径（快照列表 + 确认弹窗 + `rollback_snapshot`）。本次的替代收益已足够：用户说"改回上一版"判为 `consult` → 只读集 → 模型**物理上无法手工把文件改回去**（那正是 0004 失败模式 (b) 凭记忆重构旧内容），只能解释并引导用户用现成的回滚按钮。白拿一个 A 类收益。
- **用 LLM 分类器替换确定性阶段分流**：把可靠的状态推导换成不可靠的语义猜测，纯负收益；ADR 0003 花了一整个流水线才把阶段边界做确定，不该倒退。
- **首建轮也进分类器**：见作用域矩阵段的硬风险——风险全在、收益全无。
- **`consult` 轮入迭代日志（哪怕只记"咨询，无改动"）**：日志领域语义是改动史，咨询轮记入是纯噪音且随闲聊线性膨胀。
- **连 ADR 0004 的工具层硬闸一起拆掉**：那四层不是提示词而是物理强制，拆掉会推翻第 8 层的整个前提（预防层消失后，检测层独木难支）。本次改动是 0004"不依赖任何单层"原则的延续，不是推翻。
- **给团队工单执行单加开关跳过终结出口**：它与迭代轮共用 `_engineer_stream` 代码路径，加开关是额外复杂度，而自洽性核验对工单同样有价值（工单也会口头完成）。免费搭车。
- **删除 `ENGINEER_SYSTEM_PROMPT` 第 3、4 条、让模型纯靠撞闸门学习**：闸门报错文案确实自解释，但 `max_steps=20` 是**硬预算**，每次 `SandboxViolation` 都是一整个模型往返；撞三次墙烧掉 15% 步数，而步数耗尽 = 整轮失败 + 磁盘脏改动不留档。用一句话告知规则比撞三次墙便宜。故保留但压缩措辞。

## 后果

- **正面**：越界改动首次成为机器可判定的事（今天只有预防、无自动检测）；"口头完成"从中文措辞正则打地鼠变成一次集合比较，无漏报无误报，并新增覆盖"偷偷改了没说"这一今天完全测不到的失配；工程师主提示净变短（删掉约 200 字第 7 条），提示词从"每轮都付的主提示"迁到"按需的独立小调用"，性质从"劝模型别做错"变为"告知唯一出口 + 事后拿磁盘事实核验"；`consult` 轮零写能力、零越界可能、零产物噪音；工具事件折叠后对话主流只剩产物卡片；`touched_files` 从"解析自己发出的事件字典"归位到磁盘权威来源。
- **代价**：有改动的迭代轮 +2 次模型调用（分类器 + 裁判），延迟与 token 成本上升，且裁判发生在"工作做完之后、用户看到结果之前"，会推迟最终答复；`summary` 第一版不做流式渲染；分类器假阴性会白跑一轮（物理上改不了文件、零损坏、轮内无法自愈，靠用户下一轮纠正——已接受的不对称代价）；ADR 0004 后果段提到的 9 处集成测试迭代轮需**再改一遍**补 `submit_turn_result`；连续多轮越界且用户均选择接受期间不产生新快照，"回滚"会一次退回多轮（用户连续明确选择的结果，且预览始终是磁盘真实状态）；`Project.iteration_log` 字段语义变更（`round`→`seq`），历史项目的旧条目需在读取时兼容。
- **有意偏离、易被误"修复"处**：`consult` 轮只绑只读工具集（不是漏绑写工具）；越界轮不建快照（不是漏建）；分类器解析失败静默降级为 `modify_code`（不是缺错误处理）；裁判输入刻意不含智能体自述（不是漏传上下文）；diff 基准取磁盘而非上一个快照（不是没用现成的 `get_snapshot_diff`）；工单执行走终结出口与自洽性核验、但不走裁判也不入迭代日志。
- **后续增强（本次明确未做）**：工单执行的正确性裁判以 `Ticket.deliverable` 为诉求基准（那是拆单时写下、**经用户确认过**的事前声明，比分类器临轮猜的 `user_goal` 权威得多）；`summary` 的流式渲染（可解析 `tool_call_chunks` 增量取回打字机效果，`ThinkSplitter` 是处理这类"标签被切断在相邻 chunk"的既有先例）；`llm_utility_model` 实际切小模型；越界轮的显式「我接受，留档为版本 N+1」按钮（保持机制最少，等实际用出问题再加）。
