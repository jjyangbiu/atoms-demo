# Atoms 风格智能体应用生成平台（MVP）

> 领域术语以仓库根目录 `CONTEXT.md` 术语表为准；生成机制与向量库决策见 `docs/adr/0001`、`docs/adr/0002`。

## Problem Statement

评审者需要一个"类似 Atoms"的可在线访问的 Demo：用自然语言描述需求，由智能体驱动生成一个真实可运行的网页应用，并能在可视化界面中预览、迭代、发布与分享。现有开源方案要么只是静态演示（无真实交互），要么无数据持久化，要么缺少注册登录等完整使用流程，无法作为"实际可用"而非"概念验证"的交付物。

## Solution

一个部署在阿里云服务器上的网页应用：

1. 用户注册/登录后创建**项目**，选择**工程师模式**（单智能体直接写码）或**团队模式**（产品经理智能体先出 **PRD**，用户确认后工程师智能体再实现）。
2. 用户在对话框描述需求，**智能体**通过工具调用循环生成**多文件纯前端应用**（HTML/CSS/JS + CDN，无构建步骤），全过程**全量流式**展示（文本逐字 + "正在写入 index.html"类工具事件）。
3. 生成结果落盘托管，右侧区域可在**预览**（iframe 实时运行）与代码视图（Monaco，只读）之间切换；用户继续对话即**迭代**，每轮成功生成自动留**版本快照**（保留近 50 版），可回滚并继续迭代。
4. 用户可**发布**项目，获得任何人无需登录即可访问的稳定链接；所有已发布应用汇入 **App 世界**画廊，支持匿名浏览、语义搜索与**克隆**（复制到自己名下继续迭代）。
5. 生成质量由**模板知识库**（Milvus Lite RAG）增强；优质已发布应用可沉淀回知识库形成闭环。画廊以**官方示例**应用冷启动。

技术栈：FastAPI + LangChain + SQLite + Milvus Lite（后端），Vue 3 + Vite + Element Plus（前端），MiniMax-M3（生成）+ embo-01（embedding），Docker Compose 部署、IP 直连。

## User Stories

### 注册与登录

1. 作为一名访客，我想用用户名和密码注册账号，以便拥有属于自己的项目空间。
2. 作为一名注册用户，我想用用户名和密码登录，以便访问我的项目。
3. 作为一名注册用户，我想退出登录，以便在共用设备上保护账号。
4. 作为一名注册用户，我想在凭证错误时看到清晰的错误提示，以便知道是用户名还是密码的问题。
5. 作为一名注册用户，我想在 JWT 过期后被引导重新登录，以便系统保持安全。
6. 作为一名注册用户，我想注册已被占用的用户名时得到明确提示，以便换一个用户名。

### 项目创建与生成

7. 作为一名注册用户，我想创建一个新项目并给它起名，以便开始构建我的应用。
8. 作为一名注册用户，我想在创建项目时选择工程师模式或团队模式，以便在速度与规划质量之间做取舍。
9. 作为一名注册用户，我想在工程师模式下用一句话描述需求后智能体直接开始写代码，以便快速看到结果。
10. 作为一名注册用户，我想在团队模式下先收到产品经理智能体输出的 PRD，以便在实现前审查需求理解是否正确。
11. 作为一名注册用户，我想对 PRD 确认通过或追加修改意见，以便引导工程师智能体按我的意图实现。
12. 作为一名注册用户，我想在生成过程中逐字看到智能体的回复文本，以便确认它在朝正确方向工作。
13. 作为一名注册用户，我想在生成过程中看到工具事件（如"正在检索模板""正在写入 index.html""正在修改 styles.css"），以便了解智能体正在做什么。
14. 作为一名注册用户，我想让智能体生成包含多个文件（HTML/CSS/JS 分离）的项目，以便应用结构清晰、接近真实工程。
15. 作为一名注册用户，我想在生成失败或超时后收到明确提示并可一键重试，以便不被卡死。
16. 作为一名注册用户，我想在达到生成频率上限时被告知何时可再试，以便理解限流而非以为系统故障。

### 预览与代码视图

17. 作为一名注册用户，我想在生成完成后立即在右侧预览区看到应用真实运行效果，以便判断是否满意。
18. 作为一名注册用户，我想在"预览"与"代码"两个 Tab 之间切换，以便既能看效果又能看实现。
19. 作为一名注册用户，我想在代码视图中浏览文件树并查看每个文件的内容（Monaco 只读高亮），以便核查生成质量。
20. 作为一名注册用户，我想在迭代修改后预览自动刷新到最新版本，以便无缝继续。

### 迭代与版本

21. 作为一名注册用户，我想通过继续对话修改已生成的应用（如"把按钮改大""加一个图表"），以便持续完善。
22. 作为一名注册用户，我想让智能体只增量修改受影响文件而非重传全量，以便迭代更快、更省。
23. 作为一名注册用户，我想查看项目的版本历史列表（每轮成功生成一条），以便了解演进过程。
24. 作为一名注册用户，我想回滚到任意历史版本并在此基础上继续迭代，以便从错误方向上撤回。
25. 作为一名注册用户，我想在代码视图中对比相邻版本的差异，以便看清每轮迭代改了什么。

### 发布

26. 作为一名注册用户，我想一键发布我的项目，以便把它分享给别人。
27. 作为一名注册用户，我想让发布链接稳定不变（迭代后链接仍指向最新版本），以便分享后无需重新发链接。
28. 作为一名注册用户，我想取消发布，以便撤回不再想公开的应用。
29. 作为一名注册用户，我想看到我的项目当前是否已发布及其公开链接，以便管理我的发布。

### App 世界与克隆

30. 作为一名访客（无需登录），我想浏览 App 世界画廊中所有已发布应用（标题、描述、缩略预览），以便发现有趣的应用。
31. 作为一名访客，我想用语义搜索查找应用（如输入"记账工具"找到相关应用），以便按意图而非关键词检索。
32. 作为一名访客，我想点开画廊中的应用查看其完整运行效果，以便试用后再决定是否克隆。
33. 作为一名注册用户，我想一键克隆画廊中的应用到自己名下，以便在别人的成果上继续构建。
34. 作为一名注册用户，我想克隆后的项目保留全部文件并可立即开始迭代，以便无缝接续。
35. 作为一名注册用户，我想让我发布的优质应用沉淀进模板知识库，以便帮助后续生成更高质量的应用。

### 匿名与安全

36. 作为一名访客，我想在不登录的情况下访问画廊与任何发布链接，以便零门槛体验分享成果。
37. 作为一名访客，我想在尝试创建项目或生成时被引导去登录/注册，以便顺畅转化。
38. 作为一名注册用户，我想确信别人无法访问、修改或删除我的未发布项目，以便数据安全。
39. 作为一名平台运营者，我想对每用户生成频率与全局并发设上限，以便 API 成本可控。

### 系统初始化

40. 作为一名平台运营者，我想让系统预置 10~15 条手写模板知识条目（待办清单、计算器、图表仪表盘、落地页、小游戏、表单工具等 + 通用技术片段），以便生成质量有基线保障。
41. 作为一名平台运营者，我想让系统用自身链路生成 3~5 个官方示例应用并发布进画廊，以便画廊冷启动且克隆功能当场可演示。

## Implementation Decisions

### 后端模块划分

- **auth**：注册/登录/登出，密码哈希直接用 `bcrypt` 库（实现时修正：passlib 已停止维护，改用官方 bcrypt 库，哈希格式兼容），JWT（Bearer），用户数据隔离的依赖注入守卫。
- **projects**：项目与生成文件的 CRUD、属主鉴权、文件落盘（`{存储根}/{项目id}/` 目录，写入前做路径穿越防护，仅允许白名单扩展名）。
- **agent**：LangChain 工具调用智能体编排。工具集：`read_file` / `write_file` / `edit_file` / `search_templates`（RAG 检索）。工程师模式为单智能体循环；团队模式为两阶段（产品经理 prompt 产出 PRD → 用户确认消息 → 工程师循环）。全量流式经 SSE 推送：文本 delta 事件 + 工具调用事件 + 完成/失败事件。
- **generation-limits**：令牌桶式限流——每用户每小时生成次数上限 + 全局同时进行中的生成并发上限；超限返回 429 及重试时间。
- **snapshots**：每次成功生成后自动创建版本快照（完整文件拷贝 + 元数据），保留最近 50 版（超出的最旧快照连同文件一并清理）；回滚 = 将目标快照恢复为当前状态并作为后续迭代基线。
- **publish**：发布为项目生成稳定短 slug（随机、唯一、创建后不变），公开静态托管路径 `/p/{slug}/`；取消发布即下线。已发布项目的最新成功生成自动同步到公开目录。
- **appworld**：画廊列表（匿名）、详情、克隆（复制全部文件与元数据为新项目，归当前用户）；发布时将标题/描述/文件摘要经 embo-01 向量化写入 Milvus，语义搜索走向量检索。
- **rag**：模板知识库——启动时从种子数据（JSON/Markdown 文件）灌入 Milvus（幂等）；`search_templates` 工具按用户当前需求检索 Top-K 注入 prompt；优质发布应用沉淀走同一写入通道。
- **hosting**：nginx 与 FastAPI 协同的静态托管约定——预览 `/preview/{项目id}/`（需登录，经属主校验后重定向/代理到文件目录）、公开 `/p/{slug}/`（nginx 直接出静态）。

### 数据模型（SQLite）

- `users(id, username, password_hash, created_at)`
- `projects(id, user_id, name, mode[engineer|team], created_at, updated_at)`
- `project_files(id, project_id, path, content_hash, updated_at)` —— 文件内容以磁盘为准，此表为索引
- `messages(id, project_id, role[user|pm|engineer|system], kind[text|prd|event], content, created_at)` —— 对话历史（含 PRD 与确认）
- `snapshots(id, project_id, seq, note, created_at)` + `snapshot_files(snapshot_id, path, content)`（或快照目录拷贝，实现时可二选一，倾向目录拷贝）
- `publications(id, project_id, slug UNIQUE, title, description, created_at)` —— 一个项目至多一条活跃发布记录
- `generation_events(...)` 可选：用于审计与限流计数的生成记录

### API 契约（REST，除注明外均为 JSON；前缀 `/api`）

- `POST /auth/register`、`POST /auth/login`、`POST /auth/logout`、`GET /auth/me`
- `POST /projects`（name, mode）；`GET /projects`（我的列表）；`GET /projects/{id}`；`DELETE /projects/{id}`
- `POST /projects/{id}/messages` —— 发送用户消息并触发智能体生成，**SSE 流式响应**（事件类型：`text` / `tool` / `prd` / `done` / `error`）
- `POST /projects/{id}/prd/confirm`（团队模式：确认或附带修改意见后进入工程师阶段）
- `GET /projects/{id}/files`（文件树 + 内容，代码视图用）
- `GET /projects/{id}/snapshots`、`POST /projects/{id}/snapshots/{sid}/rollback`
- `POST /projects/{id}/publish`（title, description）、`DELETE /projects/{id}/publish`
- `GET /world`（画廊列表，匿名，支持 `q=` 语义搜索）、`GET /world/{slug}`（匿名详情）
- `POST /world/{slug}/clone`（登录）
- `GET /preview/{项目id}/...`（登录 + 属主校验）、`GET /p/{slug}/...`（公开静态，nginx 直出）

### 前端结构

- Vue 3 + Vite + TypeScript + Element Plus + Pinia + Vue Router。
- 页面：登录/注册页、工作台（我的项目列表）、项目页（核心：左侧聊天流 + 右侧预览/代码双 Tab，含模式选择、版本历史抽屉、发布对话框）、App 世界页（画廊 + 搜索 + 详情 + 克隆）。
- 聊天流渲染：Markdown 文本、工具事件时间线、PRD 卡片（含确认/修改操作区）。
- SSE 消费：原生 `EventSource` 或 fetch+ReadableStream（需携带 Authorization 时用后者）。
- Monaco Editor：以只读模式集成展示生成文件，架构上预留后续开启编辑的配置位。
- 预览：同域 `/preview/{id}/` iframe，迭代完成后刷新。

### 智能体与模型配置

- 生成模型：MiniMax-M3，OpenAI 兼容 base_url `https://api.minimaxi.com/v1`，经环境变量注入 Key；embedding：MiniMax embo-01（langchain_community.MiniMaxEmbeddings）。
- 生成物硬约束写入系统提示：仅纯前端（HTML/CSS/JS），第三方库一律 CDN，入口必须是 `index.html`，禁止构建步骤与后端依赖。
- 迭代轮次携带：系统提示 + 当前文件清单（含内容摘要）+ 最近 N 条对话 + 当前用户指令；工具调用失败自动重试有限次后以 `error` 事件收尾。

### 部署

- Docker Compose：`api`（uvicorn + FastAPI，挂载文件存储卷）、`web`（nginx：前端静态 + `/p/` 公开静态 + `/preview/` 代理与鉴权 + 反代 `/api`）。
- SQLite 与 Milvus Lite 数据、生成文件均落在命名卷/绑定挂载；配置（API Key、限流参数）经环境变量。
- 服务器为待购阿里云 ECS（建议 ≥2C4G，Ubuntu 22.04/24.04），无域名，`http://{IP}` 直连。

### 分期（砍单顺序：从 P2 倒砍）

- **P0**：注册登录、项目创建（含模式选择）、工具调用生成 + 全量流式、多文件落盘、预览、迭代修改。
- **P1**：发布 + 稳定链接、版本快照与回滚、Monaco 只读代码视图。
- **P2**：App 世界 + 克隆 + 语义搜索、模板知识库 RAG、团队模式两阶段、官方示例种子、限流。

## Testing Decisions

- **好测试的标准**：只测外部可观察行为（HTTP 响应、落盘文件、发布链接可达性、快照序列），不测内部函数与实现细节；不针对 prompt 措辞写断言。
- **主接缝（HTTP API 层）**：FastAPI TestClient 驱动真实端点，临时 SQLite + 临时文件存储目录。核心链路测试：注册→登录→建项目→生成（伪模型驱动）→预览可达→迭代→快照出现→回滚→发布→匿名访问 `/p/{slug}`→克隆→新项目属主正确。鉴权测试：未登录访问受保护端点得 401，越权访问他人项目得 404/403。限流测试：注入可控时钟验证 429 与重试头。
- **辅助接缝（LLM/工具事件边界）**：智能体编排依赖注入"可编程伪模型"——测试预先排布工具调用序列与文本输出，验证：文件确实按工具调用落盘、SSE 事件序列正确（text/tool/done）、失败重试与 `error` 事件、迭代只触碰受影响文件。任何测试不得调用真实 MiniMax API。
- **RAG 与向量**：临时目录的 Milvus Lite 实例，验证种子灌入幂等、检索返回相关模板、发布沉淀后语义搜索可命中。
- **前端**：本期不做组件级测试（工期决策），靠端到端手动走查 + 官方示例生成作为冒烟验收。
- **先行参考**：绿地项目无既有测试先例；测试骨架（conftest 中的临时目录、伪模型、测试客户端 fixture）即后续所有测试的范本。

## Out of Scope

- 生成应用的后端运行时能力（表单持久化、服务器逻辑）——生成物限定纯前端。
- 需要构建步骤的项目（Vite/打包/依赖安装）。
- Monaco 可编辑（本期只读，架构预留）。
- 邮箱验证、第三方登录、找回密码。
- 深度研究报告、赛马模式（多模型对比）。
- 多语言/国际化、移动端专项适配（桌面可用即可）。
- 生产级强化：HTTPS/域名备案、审计日志、数据备份策略、横向扩展。
- 前端自动化测试。
- 计费与用量计费展示。

## Further Notes

- **外部依赖（阻塞事实）**：① MiniMax API Key（环境变量注入）；② 阿里云 ECS 购置（≥2C4G、Ubuntu）——部署类验收在这两项就绪前无法完成，本地开发不受阻。
- **验收冒烟脚本**：注册→建项目（工程师模式）→"做一个番茄钟"→预览可用→迭代"加一个统计区"→发布→隐身窗口打开 `/p/{slug}`→另一账号克隆→继续迭代。该脚本同时是评审演示脚本。
- **官方示例**（画廊冷启动）：待办清单、数据仪表盘（ECharts）、小游戏、落地页——用系统自身链路生成，顺带全链路回归。
- **成本护栏**：限流参数保守取值（如每用户每小时 ≤10 次生成、全局并发 ≤2），避免链接外传导致 MiniMax 额度失控。
- **回退预案**：若 ECS 内存不足导致 Milvus Lite 吃力，按 ADR 0002 切换 Chroma（数据量小，重建索引即可）；若 MiniMax function calling 稳定性不达标，回退为"结构化 JSON 全量输出"（ADR 0001 已留此余地，数据模型不受影响）。
