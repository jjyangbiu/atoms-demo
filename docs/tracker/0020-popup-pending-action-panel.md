# 0020 — 弹窗式待办面板：澄清与阶段确认统一弹窗交互

**What to build:** 工程师模式的选项式澄清与团队模式的阶段确认卡（共识/规格/工单）统一改为悬浮于输入框上方的弹窗式"待办动作面板"（非居中遮罩模态），一个容器两种内容模板。问答模板（澄清）：一题一页、`1/N` 左右翻页，A–D 可点选项（含选中/悬停态），E 槽固定为"或输入自定义答案"（点选展开输入框，与字母选项互斥）；全部题目都有答案（选项或自定义）才启用"继续"，提交后答案仍作为用户消息发送，后端分流与名额语义不变。审阅模板（共识/规格/工单确认）：上部可滚动全文预览（复用现有 Markdown/工单清单渲染），下部操作栏为"确认…"按钮 + "追加意见"输入框；提交意见即收起弹窗、等待新草案再弹。行为约定：弹窗张开期间底部输入框禁用、无全屏遮罩、历史对话可滚动回看；"取消"为非破坏性收起，输入框上方留唯一"待办"重开入口（流水线串行，同一时刻至多一个 pending 动作），已选状态在收起期间保留；收起后输入框恢复可用，直接发新消息即视为待办被取代（沿用"其后存在任何消息即视为已回答/被取代"语义）；刷新/断线后尾部存在未决待办自动重弹；error 事件到达即收起弹窗。完成后对话流留只读记录卡：澄清为问答一体记录（用户答案气泡折叠进记录卡、不单独渲染，需给 `SendMessageRequest` 增加可选答案标记字段以区别"这是回答"与"这是新请求"，后端照旧以用户消息落历史）；确认为"文档摘要 + 确认状态"、可展开全文。兼容：后端 SSE 事件与消息 kind 协议（clarify/consensus/spec/tickets）不变；存量已回答的旧卡片直接渲染为只读记录卡（不折叠答案），存量尾部未答的旧卡片刷新后自动弹弹窗。按钮文案随场景自适应（澄清="继续"，共识/规格/工单="确认…"）。

**Blocked by:** 无 — 可立即开工
