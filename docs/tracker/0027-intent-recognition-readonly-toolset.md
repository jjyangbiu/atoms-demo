# 0027 — 意图识别与只读工具集

**What to build:** 迭代轮开始时先做一次独立分类，判定本轮是要改代码还是只是问问。判为咨询的轮次只绑只读工具集——写文件工具根本不存在于它的能力里，于是它物理上不可能改动任何文件，也不可能产生任何越界：磁盘零改动、无新快照、无产物卡片、不入迭代日志，回答仍逐字流式且能引用真实文件内容（不是只给路径+行数+哈希的泛泛而谈）。用户说「改回上一版」时，模型无法凭记忆手工把文件改回去——那正是 ADR 0004 的失败模式——只能解释并引导使用现成的回滚入口。分类故障静默降级为要改代码，绝不阻断用户轮次。分类与核验都不消耗生成名额。沿用澄清智能体「不绑文件工具则物理上无法写代码」的既有手法：不靠劝说，靠能力缺失。遵循 ADR 0005「第 7 层」段与规格 0021。

**Blocked by:** 0026（咨询轮不入账要求日志编号已按「改动」累积，否则编号与对话轮错位）

**Status:** ready-for-agent

- [ ] 迭代轮分流前插入一次不绑工具、不流式的分类调用，输出：意图（改动代码 / 咨询）、用户目标（一句话蒸馏复述，≤50 字）、预期触及文件路径数组
- [ ] 意图只有二值：不设问答/闲聊之分（能力边界与风险画像完全相同），不设大改/重构之分（无可执行的路由后果差异）
- [ ] 分类输入只含文件清单（路径 + 行数 + 内容哈希）、迭代日志、最近若干轮对话、用户这句话；不注入文件内容
- [ ] 解析前先洗掉行内思考标签块（推理模型会把思考过程混进正文）
- [ ] 使用 JSON Mode 承载；因其只保证语法合法、不保证字段/类型/枚举合法，服务端 schema 校验层不可省
- [ ] 校验失败或枚举越界 → 回喂错误文案让模型修正一次；仍失败则静默降级为改动代码，轮次不中断（假阳性有轮内自愈机制，假阴性没有，故不确定时一律倒向改动代码）
- [ ] 咨询轮只绑只读工具集（读取 + 模板检索），物理上不含任何写能力
- [ ] 咨询轮走流式纯文本收尾：不产生产物卡片、不做自洽性核验、不入迭代日志、不留档快照（能力边界决定核验义务——绑不到写工具就不可能产生产物，自洽性恒真）
- [ ] 首建轮不进分类器（项目尚无文件时直接走既有生成路径；首建轮的诉求在分类器眼里很像「用户在描述需求」，一旦判为咨询，应用永远建不出来）
- [ ] 克隆项目的第一条消息按迭代轮处理，进分类器
- [ ] 团队工单执行不做意图识别（内部编排而非用户对话轮）
- [ ] 澄清、需求规格、工单拆解、引导、执行引导各阶段完全不受影响；确定性阶段分流原样保留，不用 LLM 分类器替换状态机
- [ ] 分类器声明的预期触及文件只用于注入上下文与轮末比对，绝不用作沙箱硬闸（分类器看不到文件内容，猜错就卡死整轮）
- [ ] 分类蒸馏出的用户目标接入迭代日志注入内容，替代原先的截断诉求；原始诉求仍完整落库
- [ ] 分类调用不消耗生成名额：一个迭代轮无论触发几次模型调用都只占一个名额
- [ ] 新增唯一的辅助模型注入点，供分类器与后续裁判共用，未设置时回落既有模型工厂；既有测试文件与既有调用点零改动
- [ ] 测试使用 fake 模型，覆盖：咨询轮磁盘零改动且无新快照无卡片、改动轮正常执行、分类非法输出修正一次后仍失败则降级、名额只扣一次、以及「裁判/分类器不得看见智能体自述」所需的注入点隔离
