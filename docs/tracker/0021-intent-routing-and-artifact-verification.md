# 0021 — 迭代轮意图分流与产物核验

> 领域术语以仓库根目录 `CONTEXT.md` 术语表为准（本工单新增/改写：首建轮、迭代轮、意图识别、意图、只读工具集、改动范围契约、轮前指纹、自洽性核验、正确性裁决、迭代日志）。机制决策与全部被否决方案见 `docs/adr/0005`；本工单是其**增补而非替代**——`docs/adr/0004` 的第 1–4、6 层原样保留，第 5 层（迭代日志）字段调整。

## Problem Statement

用户在迭代已生成的应用时，两个问题持续存在：

**一、改动跑偏，而系统对此毫无察觉。** 用户说"把标题改大一点"，结果页脚、配色、无关组件也被顺手重写。现有六层防线里，前四层是**预防**（工具层物理闸：禁止覆写已有文件、强制先读后改、替换文本必须唯一），第六层是**检测**——但检测靠用户自己打开 diff 面板**肉眼比对**。系统从来不知道"这一轮改的东西超出了用户要求的范围"：它只记录改了哪些文件，从不校验该不该改这些文件。

**二、对话被与需求无关的信息淹没。** 每个工具调用都在对话主流里平铺一行记录；模型的总结里夹带"我先读取了某文件、然后调用了编辑工具"这类过程复述；系统还会在回复正文末尾追加一段核验说明文案。用户想看的只有两件事：这一轮改了什么、改得对不对。

第二个问题的根源是一整套**靠猜中文措辞**的守卫机器：为了判定"模型是不是没动手就声称改完了"，仓库里堆了 19 个固定短语、4 个正则族、一条三级升级链（劝说 → 注入磁盘事实 → 放弃并追加标注）、以及系统提示里一段约 200 字的"严禁口头完成"条款。代码注释自己承认"固定词表穷举不尽实际措辞""宁可偶有误报，不可漏报"——这是在给一个**本该确定性**的判断打自然语言补丁。而工程师智能体是仓内**唯一没有结构化出口**的智能体：澄清智能体的唯一出口是产出需求共识的工具，拆单智能体的唯一出口是提交工单清单的工具，两者都是结构化数据走工具参数 + 服务端校验 + 非法回喂修正 + 兜底恢复。工程师智能体却靠自由文本收尾，于是只能事后用正则去猜文本里的语义。

## Solution

给迭代轮加两层，都是**物理约束与确定性判定**，不是更多的劝说：

**第 7 层·意图分流（决定能力边界）。** 迭代轮开始时先做一次独立分类，判定本轮是"要改代码"还是"只是问问"。判为咨询的轮次只绑定**只读工具集**——写文件工具根本不存在于它的能力里，于是它**物理上不可能**改动任何文件，也不可能产生任何越界。这沿用澄清智能体"不绑文件工具则无法提前写代码"的既有手法：不靠劝说，靠能力缺失。

**第 8 层·产物核验（声明与事实成对比对）。** 要改代码的轮次，其唯一合法收尾方式是提交一份结构化的**轮次产物**：本轮意图、给用户看的一句话总结、声明改动的文件清单。轮末系统做两层相互独立的核验：

- **自洽性核验**（确定性代码、零成本）：把模型**声明**改了什么，与磁盘上**真实**改了什么做集合比较。这一层单独就覆盖了"口头完成"（声明有改动、磁盘零改动）、"偷偷改了没说"（声明零改动、磁盘有改动，今天完全测不到）、以及"文件集不符"三种失配——**整套中文措辞正则机器由此退役**，且新判定无漏报、无误报、不需要穷举措辞。
- **正确性裁决**（独立调用）：自洽性只证明模型说了真话，不证明它干的是用户要的事。由一个独立裁判比对**用户原话**与**代码已算好的真实 diff**，判定改动是范围内、越界、还是未完成。裁判**看不到智能体的任何自述**——否则就是让模型给自己打分。

核验不通过时的处置以**不擅自做破坏性决定**为原则：越界改动列出具体文件与段落、**不升格为正式版本**、交用户裁决接受或回滚；未完成只标注、照常留档。

对话随之变干净：模型的散文总结通道被关闭（总结只经结构化出口产出），系统核验结论从"追加在回复正文末尾的文案"变成"产物卡片上的结构化徽标"，工具调用记录仍然完整落库（刷新可回看、排查有证据链）但**默认折叠为一行轮次摘要**。

## User Stories

### 意图分流与能力边界

1. 作为一名注册用户，我想在只是提问时系统不改动我的任何文件，以便我能放心询问而不担心应用被意外改坏。
2. 作为一名注册用户，我想在问"某个效果是在哪里实现的"时得到能引用真实文件内容的回答，以便我真的能定位到代码，而不是收到一段泛泛而谈。
3. 作为一名注册用户，我想在说"算了还是改回上一版"时被引导去用版本回滚，而不是让智能体凭记忆手工把文件改回去，以便撤回是可靠且可逆的。
4. 作为一名注册用户，我想在我确实要求修改时系统不会因误判而拒绝动手，以便我的诉求不被吞掉。
5. 作为一名注册用户，我想在系统误判我的意图时最多损失一轮对话、而不是损失我的文件，以便误判的代价可控且可自愈。
6. 作为一名注册用户，我想在首次从零生成应用时不被意图分流拖慢或误判，以便第一版能顺利产出（首建轮没有旧文件可越界，进分类器是风险全在、收益全无）。
7. 作为一名注册用户，我想在克隆别人的应用后，第一条消息就被当作迭代处理，以便我能立刻在已有成果上继续改。
8. 作为一名注册用户，我想在团队模式的澄清、需求规格、工单拆解、执行引导阶段保持原有的确定性流程，以便这些阶段不因新增的意图识别而变得不可预测。
9. 作为一名注册用户，我想让"要改代码"与"只是问问"成为仅有的两类意图，以便分类面越窄、误判越少（问答与闲聊的能力边界和风险画像完全相同，大改与小改的差异由预期触及文件承载而非意图类别）。

### 轮次产物卡片与对话整洁

10. 作为一名注册用户，我想在一轮修改结束后看到一张结构化卡片：一句话总结 + 改了哪些文件 + 核验结论，以便一眼看清这一轮的结果。
11. 作为一名注册用户，我想让对话主流里不再平铺一条条工具调用记录，以便我读对话时不被过程噪音淹没。
12. 作为一名注册用户，我想在需要时展开查看本轮完整的工具调用明细，以便排查问题时证据链仍然完整。
13. 作为一名注册用户，我想在刷新页面后看到与刷新前一致的历史（含折叠的过程摘要与产物卡片），以便过程可回看。
14. 作为一名注册用户，我想让模型的回复里不再出现"我调用了某工具、然后又调用了某工具"这类过程复述，以便回复只包含对我有用的信息。
15. 作为一名注册用户，我想让系统的核验结论以卡片上的徽标呈现，而不是追加在模型回复的正文末尾，以便核验信息结构化、可扫读，且不混进模型的话里。
16. 作为一名注册用户，我想在纯提问轮看到逐字流式的回答，以便对话保持即时感。
17. 作为一名注册用户，我想从产物卡片直接展开看这一轮的 diff，以便核对改动细节。
18. 作为一名注册用户，我想让思考过程保持默认折叠的现状，以便它继续作为可选的过程信息而不构成噪音。

### 越界改动的核验与处置

19. 作为一名注册用户，我想在系统发现智能体改了我没要求改的地方时，被告知具体是哪个文件的哪一段，以便我能判断要不要接受。
20. 作为一名注册用户，我想在出现越界改动时由我决定接受还是回滚，以便系统不擅自替我做破坏性决定。
21. 作为一名注册用户，我想在我选择接受越界改动后它自然并入下一个正式版本，以便我不需要任何额外的"保存"操作。
22. 作为一名注册用户，我想在我选择回滚时精确丢弃这一轮的越界改动，以便撤回是干净的。
23. 作为一名注册用户，我想在智能体声称改好了、但磁盘上什么都没变时被明确告知，以便我不被假进展误导。
24. 作为一名注册用户，我想在智能体偷偷改了文件却没申报时也被系统抓到，以便"少报"和"多报"都逃不过核验。
25. 作为一名注册用户，我想在智能体只完成了一半诉求时看到"未完成"标注，以便我知道还要继续推动。
26. 作为一名注册用户，我想让核验由系统基于磁盘事实完成、而不是让模型自评，以便结论可信。
27. 作为一名注册用户，我想让裁判在判定时看不到智能体对自己改动的描述，以便它不是在被引导的情况下打分。
28. 作为一名注册用户，我想在改动完全在范围内时得到干净收尾，以便正常情况下没有任何额外打扰。
29. 作为一名注册用户，我想让"该不该改这一处"按区域而非按文件判定，以便同一个文件里的越界重写也能被抓到。

### 版本快照语义

30. 作为一名注册用户，我想让版本列表里的每一版都是系统认可的正式版本，以便回滚目标都是有意义的。
31. 作为一名注册用户，我想让越界改动轮不自动升格为一个正式版本，以便版本列表不被污染（与"零改动轮不留档"是同一条理由的延伸）。
32. 作为一名注册用户，我想让零改动轮不产生新版本，以便不出现"版本 N+1"的假进展。
33. 作为一名注册用户，我想在预览里始终看到磁盘的真实状态（即使这一轮没留档），以便我看到的永远是当前实际效果。
34. 作为一名注册用户，我想让某轮不留档之后的下一轮改动范围仍然算得准，以便核验基准不会因为快照序列与磁盘脱钩而错位。

### 降级与可靠性

35. 作为一名注册用户，我想在核验服务自身故障时仍然拿到我的改动成果，以便安全网故障不吞掉我的劳动。
36. 作为一名注册用户，我想在核验未能完成时看到明确的"核验未完成"标注，以便我知道该自己去核对 diff，而不是被静默放过。
37. 作为一名注册用户，我想在智能体不按规定出口收尾时系统仍能兜底给我一个结果，以便轮次不会卡死。
38. 作为一名注册用户，我想在智能体把结构化产物写进正文而没走工具时系统尽力恢复出它，以便不因格式问题浪费一整轮。
39. 作为一名注册用户，我想在兜底路径下系统一律以磁盘真实改动为准、绝不采信模型的申报，以便模型不配合时核验依然有效。
40. 作为一名注册用户，我想在意图分类失败时系统保守地按"要改代码"处理，以便我的修改诉求不被静默丢弃（假阳性有轮内自愈机制，假阴性没有）。
41. 作为一名注册用户，我想在任何一轮都只消耗一个生成名额、分类与核验不额外扣，以便我说一句话不会被扣三次。
42. 作为一名注册用户，我想在智能体超过步数上限时得到明确的失败提示、且不留一个伪装成功的版本，以便失败是显式的。

### 迭代日志与跨轮记忆

43. 作为一名注册用户，我想让系统在多轮之后仍然记得早期改过什么，以便长对话里不出现"忘了项目演进到哪"的漂移。
44. 作为一名注册用户，我想让日志里的编号对应"第几次改动"而不是"第几轮对话"，以便我引用"上一次改动"时系统理解正确（咨询轮不入账会让两种编号错位）。
45. 作为一名注册用户，我想让纯提问轮不写入改动日志，以便日志不被闲聊稀释、不随闲聊线性膨胀。
46. 作为一名注册用户，我想让日志记下越界与未完成的核验结论，以便后续轮次能理解磁盘为什么是现在这个样子。
47. 作为一名注册用户，我想让日志注入的是我诉求的蒸馏版、而原始诉求仍完整留档，以便上下文省 token 但不丢权威数据。

### 团队模式

48. 作为一名团队模式用户，我想让工单执行也走同一个结构化出口与自洽性核验，以便工单也不会"口头完成"。
49. 作为一名团队模式用户，我想让工单执行不被计入迭代日志、不做意图识别，以便内部编排指令不被当成我的发言。
50. 作为一名团队模式用户，我想让工单执行保持原有的检查点语义，以便回滚与续跑行为完全不变。

### 运营、成本与落地

51. 作为一名平台运营者，我想让分类与核验调用可以切到更便宜的小模型（改一个配置即可），以便成本可控而不必改代码。
52. 作为一名平台运营者，我想让裁判先以"只标注不阻断"的方式上线一段时间，以便在拿到真实误判率之前不让它决定版本留档。
53. 作为一名平台运营者，我想让本次改动分五步落地、每步可独立验证与回退，以便风险可控。
54. 作为一名平台运营者，我想让整套中文措辞正则机器被退役，以便不再维护一个靠穷举词表打补丁的守卫。
55. 作为一名平台运营者，我想让工程师主提示净变短，以便每轮都要付的 token 减少，而新增的提示词迁移到按需触发的独立小调用里。

## Implementation Decisions

### 模块改动面

- **智能体循环模块**：新增"唯一终结出口"语义与一次精确回喂；**移除**口头完成的措辞检测、三级升级链、以及"注入磁盘事实"的劝说式回喂。循环对模型实现的约定不变（可选流式、可选工具绑定、非流式回退），因此可编程伪模型仍走完全相同的代码路径。
- **沙箱工具层**：新增"本轮真实改动文件集"的权威记录，与既有的"本轮已读文件集"同构。**ADR 0004 第 1–4 层闸门（禁止覆写已有文件、先读后改、替换文本四级定位、零 diff 空操作报错）一律原样保留**，它们不是提示词而是物理强制。工具集需支持构建**只读变体**（读取 + 模板检索，不含任何写能力）。
- **项目路由**：迭代轮分流前插入分类调用；收尾逻辑改为"以磁盘指纹比对为权威、按核验结论决定是否留档快照"；工具事件的落库保持不变（既有契约：刷新可回看完整过程）。
- **提示词模块**：工程师系统提示删除"严禁口头完成"整条，第 3、4 条（修改只能用编辑工具、替换文本必须唯一、只动受影响区域）**保留但压缩**——闸门报错文案虽自解释，但步数上限是硬预算，每次违规都是一个完整的模型往返，用一句话告知规则比让它撞三次墙便宜。新增分类器提示词与裁判提示词，两者都是独立小调用、不进工程师主提示。
- **迭代日志**：条目结构与渲染文案调整（见下）。
- **配置**：新增一个"辅助模型"配置项，默认等于主模型。

### 契约：意图分类（轮次开始，不绑工具、不流式）

输出结构：意图（`modify_code` | `consult`）、用户目标（一句话蒸馏复述，≤50 字）、预期触及文件（路径数组）。

- 意图只有二值。不设 `question`/`chitchat` 之分（能力边界与风险画像完全相同），不设 `big_change`/`refactor`（无可执行的路由后果差异，允许动几个文件由预期触及文件承载），不设 `rollback`（见 Out of Scope）。
- 输入只含：文件清单（路径 + 行数 + 内容哈希）、迭代日志、最近若干轮对话、用户这句话。**不注入文件内容**——分类器看不到内容，因此它的范围声明只用于注入上下文与轮末比对，**绝不用作沙箱硬闸**（猜错就卡死整轮）。
- 载体：该调用不绑工具，故用 JSON Mode（`response_format` 的 `json_object`）。JSON Mode **只保证语法合法**，不保证字段/类型/枚举合法，因此**服务端 schema 校验层不可省**。解析前必须先洗掉行内思考标签块（推理模型会把思考过程混进正文，仓库已有现成的清洗函数）。
- 校验失败或枚举越界：照既有房规回喂错误文案让模型修正一次；仍失败则**静默降级为 `modify_code`**。分类器故障绝不阻断用户轮次。

### 契约：轮次产物（`modify_code` 轮的唯一合法出口）

以工具调用为载体的终结出口，参数结构：自报意图（`modify_code` | `no_change`）、给用户看的中文总结（Markdown，简短）、声明改动的文件路径数组、无需改动时的理由。

- 自报意图可以与分类器的判定不同——这是**逃生舱**：分类器假阳性把一轮送进了工具循环，模型读完文件发现无需改动（用户只是询问、或目标状态已存在于磁盘），就自报 `no_change` 合法收尾，不触发任何惩罚。原则是**分类器只决定能力边界，不决定义务**。
- 声明改动只到**文件级**。区域级判断交给独立裁判；让模型自报"我改了第几行到第几行"只增加它的负担和分歧面，而那份声明对正确性裁决毫无价值（裁判本来就不该看被裁判者的自述）。
- 走工具参数而非 `response_format`，因为**`response_format` 与工具绑定是两条互斥的输出通道**：绑了工具还强制 JSON 输出，模型往往倾向吐 JSON 而不去调工具，循环直接断掉。这也与仓内既有的两处结构化出口（需求共识、工单清单）保持同一范式。

### 契约：正确性裁判（独立调用，不绑工具）

- **触发条件收窄**：仅 `modify_code` 轮 **且** 磁盘真有改动时触发。咨询轮与零改动轮一分不花。
- **输入**：用户原话 + 最近若干轮上下文 + 代码已经算好的 diff（hunk 由标准库定位并附行号，**不让裁判自己数行**，压缩幻觉面）。
- **输入禁区**：不得包含智能体的任何自述——总结、自报意图、声明改动文件、以及分类器产出的用户目标，全部不给。否则裁判退化为"让模型给自己打分"。
- **输出**：裁决（`in_scope` | `out_of_scope` | `incomplete`）+ 越界段落清单（文件、行区间、理由）。

### 核验与处置规则

| 核验结果 | 处置 | 留档快照 |
|---|---|---|
| 自洽性失配 | 把"你声明的 vs 磁盘实际的"精确差异回喂一次；仍失配则标注收尾 | 视最终磁盘状态 |
| `out_of_scope` | 列出越界段落 + 交用户裁决（接受 / 回滚上一版） | **否** |
| `incomplete` | 标注未完成 | 是（改动合法、只是没做完，不该惩罚） |
| `in_scope` | 干净收尾 | 是 |

**越界轮不留档的理由是语义的**：版本快照是"某次成功生成后的完整留档、可回滚"，越界改动不该被自动升格为系统认可的正式版本，那会污染回滚列表。副作用是**无需新增任何"接受并留档"机制**：快照是全量文件留档，用户若接受，越界改动自然被下一次成功轮的快照吸收；若选择回滚上一版，恰好就是丢弃这一轮。

**被明确否决的处置**：裁判自动回滚越界段落（把不可逆的破坏性操作建立在概率判断上；多处改动交织时按段还原可能产出语法破碎的文件；ADR 0004 已以同一理由否决行级自动回滚）；把裁决回喂让模型自动返工（延迟叠加，且模型自纠越界极易引入新的越界）。

### 权威来源归位

"本轮改了哪些文件"今天是靠**解析系统自己发给前端的流式事件字典**收集来的，而参数摘要逻辑会截断超长字段——它却承担着"是否留档快照 / 迭代日志记什么 / 是否发无改动警告"三重硬闸职责。这是运气不是设计。改为：**磁盘轮前指纹与轮后指纹的比对是唯一权威来源**，沙箱记录作为辅助。事件行退回它本来的职责——给人看的过程记录，不再兼任系统判据。

### 快照与 diff 基准

**diff 基准必须取磁盘，不能取上一个快照。** 越界轮不留档会使快照序列与磁盘序列脱钩，若用"快照 vs 前一快照"当基准，脱钩之后每一轮的改动范围都会算错。轮前指纹取磁盘当前状态，轮末重算即得真实改动集。

### 作用域矩阵

| 轮次 | 分类器 | 只读工具集 | 终结出口 | 自洽性核验 | 正确性裁判 | 产物卡片 | 入迭代日志 |
|---|---|---|---|---|---|---|---|
| 首建轮（项目尚无文件） | ✗ | ✗ | ✓ | ✓ | ✗ | ✓ | ✓ |
| 迭代 · `modify_code` | ✓ | ✗ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 迭代 · `consult` | ✓ | ✓ | ✗ | ✗ | ✗ | ✗ | ✗ |
| 团队工单执行 | ✗ | ✗ | ✓ | ✓ | ✗ | ✓ | ✗ |
| 澄清 / 规格 / 拆单 / 引导 / 执行引导 | 完全不受影响 | | | | | | |

切分线的原理：**自洽性核验免费且不需要额外上下文，故覆盖所有会写文件的工程师轮次；正确性裁判需要 +1 次调用且需要诉求基准，故只覆盖迭代轮。**

- 首建轮裁判为 ✗：没有旧文件，"越界"这个概念不存在，全是新建。
- 首建轮不进分类器：其诉求在分类器眼里很像"用户在描述需求"，一旦判为咨询走只读集，**应用永远建不出来**。
- 咨询轮终结出口为 ✗：**能力边界决定核验义务**——绑不到写工具就不可能产生产物，没有产物可校验，自洽性恒真。走流式纯文本收尾，白拿回打字机效果。
- 工单执行走终结出口与自洽性核验：它与迭代轮**共用同一条工程师流代码路径**，单加开关跳过是额外复杂度，而自洽性核验对工单同样有价值（工单也会口头完成）。免费搭车。
- **确定性阶段分流原样保留**，不用 LLM 分类器替换状态机——那是把可靠的状态推导换成不可靠的语义猜测，纯负收益。

### 迭代日志变更

- 条目按「改动」而非「对话轮」累积：序号字段语义从"第 N 轮"改为"第 N 次改动"，渲染文案同步改名。咨询轮不入账后两种编号会错位，继续叫"第 N 轮"等于对模型说谎。
- 注入内容用分类器蒸馏的用户目标（≤50 字）替代原始的截断诉求；但**原始诉求仍然落库**——蒸馏版是模型写的、可能失真，原话才是权威数据。原则：权威数据留档，token 花在蒸馏版上。
- 新增核验结论字段。越界轮虽不留档快照，改动却留在磁盘上，**必须**留这条日志，否则后续轮次无从理解磁盘为什么是现在这个样子。
- 咨询轮不入账：日志存在的唯一理由是跨对话窗口存活，而近期问答本就在窗口内——**需要跨窗口存活的是改动，不是问答**。
- 净 token 账：蒸馏目标换掉截断诉求、加核验结论几个字，每条持平或更短；咨询轮不入账直接砍掉一类膨胀源。故**暂不设截断上限**，不预先优化。
- **历史兼容**：存量项目的日志条目仍是旧结构（旧序号字段名、无核验结论），读取时必须兼容渲染，不得因缺字段报错。

### 消息与流式协议变更

- 新增一个消息类型承载完整的轮次产物（自报意图、总结、声明改动、核验裁决、越界段落清单、无需改动的理由）。它以结构化数据落库，前端渲染为卡片。**不再**把系统核验说明以文案形式追加进模型回复正文。
- 流式收尾事件移除既有的"无改动警告"布尔与文案字段，改为携带核验结论与产物摘要。收尾事件仍是流的最后一个事件（既有约定：落盘完成后才外发）。
- 工具事件的落库契约不变（刷新可回看完整过程、排查有证据链）；**变化只在前端渲染**：默认折叠为一行轮次摘要，可展开看明细。这是纯渲染层决策，风险最低、可独立回退。
- 咨询轮的回复走流式纯文本，落库为普通文本消息，不产生产物卡片。

### 降级铁律

**核验是安全网；安全网故障不得扣住用户的劳动成果，也不得让轮次卡死。** 预防靠 ADR 0004 的四层物理闸，它们不依赖任何模型配合。

- 裁判失败（网络/超时/非法输出）→ 重试一次（复用既有的重试次数与退避语义），仍失败则标注"核验未完成"、**快照照建**。反方意见（越界会溜过去）由第六层 diff 面板与项目级回滚兜底，且"核验未完成"徽标把安全网故障**显式化**而非静默吞掉。
- 模型不走终结出口 → 照既有房规从后往前扫描正文里的 JSON 候选起点、解析失败补右括号重试；仍无则回喂一次"你的唯一出口是提交轮次产物"，再不听就以该散文作总结兜底收尾。
- **兜底路径下声明改动一律以磁盘真实值填充，绝不采信模型申报**——兜底恰恰是模型不配合的场景，此时采信自报等于放弃核验。
- 步数耗尽：维持现状（不留档快照、磁盘留着脏改动），与"越界轮不留档"语义天然一致。
- 分类器假阴性（想改被判咨询）：**不做任何补偿机制**——不加提示文案（又一条散文噪音）、不做"我想修改"快捷重发（过度设计）。代价是白跑一轮、零文件损坏，用户下一轮纠正即可。这是已明确接受的不对称代价。

### 成本与限流

- 分类器与裁判**都不消耗生成名额**，名额判定保持"一轮对话一个名额"。名额的领域语义是"用户发起一轮生成"，二者是这一轮的内部开销；让它们吃名额，用户体感会是"我说一句话被扣了三次"。
- 但成本是真的：有改动的迭代轮从 `1 + N`（N 为工具步）变为 `1 + N + 1`。新增的辅助模型配置项默认等于主模型，**本次不切小模型**（避免引入未验证的第二个模型），但分类与裁决都是"输入小、输出小、不需要强推理"的任务，是切小模型的完美候选——实测成本或延迟有问题时改一个配置即可切，不用改代码。
- 提示词总量**并没有减少**（新增分类器提示词与裁判提示词）。真正的改善是位置与性质的迁移：从"每轮都要付 token 的工程师主提示"迁到"按需触发的独立小调用"，工程师主提示净变短；从"劝模型别做错"（软约束、会漂移、需要正则打地鼠兜底）变为"告知唯一出口在哪 + 系统事后拿磁盘事实核验"（物理约束 + 确定性判定）。

### 数据模型

**无需 DDL 变更、无需迁移脚本**：迭代日志是既有的 JSON 列（条目结构变更在读取侧兼容），新消息类型复用既有的字符串 kind 列。

### 分期（五步，每步可独立验证与回退）

原则：**先做确定性收益，再做概率性机制。**

1. **"本轮改了哪些文件"的权威来源重构**（沙箱记录 + 轮前/轮后指纹比对）。纯内部重构、零行为变化，但必须最先做——**改动集本身若不可信，自洽性核验与裁判都建在沙上**。
2. **终结出口 + 自洽性核验 + 退役整套措辞正则机器 + 产物卡片 + 迭代日志字段调整**。不引入任何新模型调用，是全部价值的大头；完成后即使 3/4/5 全部回退也已净赚。
3. **意图分类器 + 只读工具集 + 蒸馏目标接入日志**。第一个新调用点。
4. **正确性裁判 + 越界处置**。第二个新调用点，最需观察误判率。
5. **前端工具事件折叠**。纯渲染层，随时可做、可独立回退。

**裁判处置分两阶段上线**：阶段一只标注不阻断（越界轮照常留档快照、卡片把越界段落标红），收集真实误判率；阶段二确认误判率可接受后才启用"越界轮不留档"。裁判是 LLM 而我们手上没有任何误判率数据，一上线就让它决定是否留档版本，其缺陷会静默破坏版本存档链路且用户难以归因（他只看到"版本列表怎么不涨了"）。阶段一让它在**无破坏力**的位置上先证明自己。

## Testing Decisions

- **好测试的标准**（沿用规格 0001）：只测外部可观察行为——HTTP 响应与流式事件序列、落盘文件内容、快照序列、落库消息的类型与内容、版本列表——**不测内部函数与实现细节，不针对提示词措辞写断言**。任何测试不得调用真实模型服务。

- **主接缝：HTTP API 层**（既有，优先使用）。测试客户端驱动真实端点，临时数据库 + 临时存储根 + 临时向量库。本次新增的全部机制在这个接缝上都是可观察的，**不需要为它们开新接缝**：
  - 意图分流 → 咨询轮**物理上写不了文件**：预置项目文件、脚本安排分类为咨询，断言磁盘内容未变、无新快照、无产物卡片消息。
  - 终结出口 → 断言流式事件序列与落库的产物消息类型及其结构化内容。
  - 自洽性核验 → 脚本安排"声明改动为空但实际调用了编辑工具"，断言核验结论标出失配；反向安排"声明有改动但磁盘零改动"，断言口头完成被确定性抓到（不依赖任何措辞）。
  - 正确性裁判 → 脚本安排三种裁决值，分别断言：越界轮不留档快照且卡片列出越界段落、未完成轮照留档且带标注、范围内轮干净收尾。
  - **脱钩回归**（最容易被忽略、且会静默产出错误核验结论的交互）→ 连续两轮：第一轮判越界故不留档，第二轮断言其改动范围基准仍取磁盘而非上一个快照。
  - 降级 → 裁判调用抛异常，断言重试后标注"核验未完成"且快照照建；分类器返回非法 JSON，断言修正一次后仍非法则降级为要改代码且轮次不中断；模型不走终结出口而把 JSON 写进正文，断言恢复成功；模型只输出散文，断言回喂一次后以散文兜底收尾且声明改动取磁盘真实值。
  - 名额 → 断言一个迭代轮无论触发几次模型调用都只消耗一个名额。

- **辅助接缝：模型注入点**（既有一个 + 新增一个）。既有接缝是应用状态上的模型工厂，注入可编程伪模型；伪模型满足循环的最小约定（工具绑定 / 非流式调用 / 可选流式），因此与真实客户端走完全相同的代码路径。
  - **新增唯一一处注入点**：应用状态上的"辅助模型工厂"，供分类器与裁判使用，**未设置时回落到既有模型工厂**。加默认回落意味着现有全部测试文件与既有调用点零改动。多工厂并存是既有房型（桩 embedding 工厂本来就与模型工厂并存）。
  - 否决的替代：为分类器与裁判各开一个工厂（多开接缝而无额外收益——分类器恒为第一次调用、裁判恒为最后一次，二者永不重叠，共用一个工厂按序排布脚本即可）；把既有工厂改成角色参数化（改了既有接缝的签名，要动所有测试的注入 helper 与全部调用点，收益与加法式方案相同）。
  - 该注入点让"裁判不得看见智能体自述"这条性质变得可断言：在工程师的总结里塞一个唯一标记串，断言它**不出现**在辅助伪模型收到的裁判那一批消息里。

- **沙箱单元接缝**（既有）：ADR 0004 的工具层闸门本来就是直接驱动沙箱测试的，本次沿用——第 1 步的"本轮真实改动文件集"记录与只读工具集变体在这个接缝上测。先例是既有的编辑工具与写入工具测试。

- **共享脚本步常量**（沿用既有房规，如首建澄清步常量）：测试骨架里新增分类步（要改代码 / 咨询）、裁决步（范围内 / 越界 / 未完成）、终结出口步的共享常量，以及一个注入辅助伪模型的 helper。

- **必须认账的机械改造**：ADR 0004 后果段提到约 9 处集成测试的迭代轮曾补过"先读后改"步骤；终结出口成为强制后，**这些脚本末尾的纯文本收尾步都要换成终结出口步**。此外，专门针对措辞检测、三级升级链、无改动警告字段的既有测试会**整体作废**，需按自洽性核验重写——这是退役清单的直接后果，不是意外损失。

- **前端**：照既有约定不做组件级测试（规格 0001 的工期决策）。产物卡片、工具事件折叠、越界段落标红靠端到端走查脚本验证（既有走查脚本目录已有先例），加上类型检查构建通过。

## Out of Scope

- **工单执行的正确性裁判**。工单其实有一个比分类器临轮猜测**更权威**的诉求基准——工单的交付内容，那是拆单时写下、**经用户确认过**的事前声明。这是真正有价值的后续增强，但不该混进本次改动。
- **总结的流式渲染**。可以解析工具调用参数的增量片段取回打字机效果（仓库已有处理"标签被切断在相邻片段"的先例），但复杂度实打实；循环中的思考流与工具事件已提供"正在进行"的反馈，故第一版收尾一次性出卡。
- **实际切换辅助小模型**。本次只加配置项并默认等于主模型，不引入未验证的第二个模型。
- **越界轮的显式「我接受，留档为版本 N+1」按钮**。越界改动会被下一次成功轮的快照自然吸收，机制已闭合；保持机制最少，等实际用出问题再加。
- **`rollback` 意图**。让分类器触发破坏性操作有风险，且回滚已有确定性 UI 路径（版本列表 + 确认弹窗 + 回滚端点）。本次的替代收益已足够：用户说"改回上一版"判为咨询 → 只读工具集 → 模型**物理上无法手工把文件改回去**（那正是 ADR 0004 失败模式"凭记忆重构旧内容"），只能解释并引导用户用现成的回滚按钮。
- **用分类器声明的预期触及文件做沙箱硬闸**（越界编辑直接拒）。分类器看不到文件内容，猜错就卡死整轮（改个按钮颜色常要同时动结构与样式）。声明范围只用于注入上下文与轮末比对。
- **用 LLM 分类器替换确定性阶段分流**。
- **首建轮进分类器**。
- **咨询轮写入迭代日志**（哪怕只记"咨询，无改动"）。
- **行级/段落级自动回滚、自动返工**。
- **拆除 ADR 0004 的工具层物理闸门**。那四层不是提示词，拆掉会推翻第 8 层的整个前提（预防层消失后，检测层独木难支）。
- **删除工程师系统提示第 3、4 条、让模型纯靠撞闸门学习**。步数上限是硬预算，撞墙成本高于告知成本。
- **迭代日志的截断/聚合上限**。净 token 账持平或更短，暂不预先优化。
- **前端组件级测试与自动化测试框架引入**。
- **原生 JSON Schema 严格模式**。MiniMax 全系支持的是 JSON Mode（只保证语法合法），服务端校验层无论如何省不掉；若实测严格 schema 可用可作后续升级，但校验层仍保留（它同时是自洽性核验的落点）。

## Further Notes

- **与 ADR 0004 的关系必须在实施时反复申明**：本次是第 7、8 层的**增补**。有意偏离、易被后来者误"修复"的地方共六处——咨询轮只绑只读工具集（不是漏绑写工具）；越界轮不留档快照（不是漏建）；分类器解析失败静默降级为要改代码（不是缺错误处理）；裁判输入刻意不含智能体自述（不是漏传上下文）；diff 基准取磁盘而非上一个快照（不是没用现成的快照比对端点）；工单执行走终结出口与自洽性核验、但不走裁判也不入迭代日志。实施时这六处都需要就地注释说明。

- **需要实测验证的外部事实**（构成方案风险，不阻塞开工）：① MiniMax 在 OpenAI 兼容路径下 JSON Mode 的实际行为，尤其**绑定工具时是否仍接受 `response_format`**——本设计已把结构化载体按"有无工具"分到两条通道，正是为了绕开这个不确定性；② 推理模型的行内思考标签块在 JSON Mode 下是否会污染输出（已有现成清洗函数可复用）；③ 工具调用参数增量片段的可流式性（影响 Out of Scope 里的总结流式渲染）。

- **验收冒烟脚本**（同时是演示脚本）：预置一个多文件项目 → 发一句纯提问 → 断言磁盘零改动、无新快照、无产物卡片、回复逐字流式 → 发一句"把标题改大一点" → 断言产物卡片出现、只改了该改的文件、快照 +1 → 人为制造一次越界（脚本安排裁判判越界）→ 断言快照不增、卡片列出越界段落 → 再发一轮正常修改 → 断言其改动范围基准正确（越界轮的改动被算作基线的一部分）→ 打开版本列表回滚 → 断言越界改动被丢弃。

- **术语表已同步**：本次访谈过程中已就地更新仓库根目录的领域术语表——修正了「迭代」词条与 ADR 0004 硬闸的既有矛盾（原文说每轮迭代都产生版本快照，而零改动轮硬闸明确不留档），并新增首建轮、迭代轮、意图识别、意图、只读工具集、改动范围契约、轮前指纹、自洽性核验、正确性裁决九条，改写迭代日志的定义为按改动而非对话轮累积。

- **回退预案**：五步分期本身就是回退预案——步骤 2 完成后即使 3/4/5 全部回退，项目也已净赚（措辞打地鼠换成集合比较、散文噪音换成结构化卡片）。步骤 4 的裁判另有阶段一"只标注不阻断"作为无破坏力的观察期，误判率不可接受就停在阶段一，越界信息仍然呈现给用户，只是不再影响版本留档。
