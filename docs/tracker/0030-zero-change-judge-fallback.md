# 0030 — 可疑零改动轮的裁判兜底（谎称「无需改动」不再拿绿色徽标过关）

**What to build:** 用户轮存在一条「说改好了但没改」的逃逸口：分类器判 modify_code、模型却以结构化 no_change 收尾（或散文兜底被系统按磁盘事实合成为 no_change）且磁盘零改动——自洽性核验无从比对（申报与磁盘「一致」地都是零），卡片拿绿色 CONSISTENT 徽标直接过关，0028 的裁判因「零改动轮不进裁判」永不触发。本工单让这类「可疑零改动轮」带空 diff 照常进裁判：裁判读用户原话裁决——诉求要求改动却零改动 → incomplete（卡片「未完成」徽标显式标注）；诉求本就不要求改动（确认现状、「不要改」类良性诉求，分类器规则 2 不确定时偏向 modify_code 造成的误报）→ in_scope 干净收尾。嫌疑信号是确定性代码判定（分类 intent、终结出口 intent、磁盘指纹三者合成），不新增任何模型调用；裁决本身交给已就位的裁判（0028 阶段一只标注不阻断语义不变：不回喂、不返工、零改动轮照旧不留档快照）。分类缺席（辅助模型降级）无嫌疑信号，不触发裁判——静默降级房规照旧。前端零改动（复用既有 scope_verdict 卡片字段与徽标渲染）。

**Blocked by:** 0027（意图分类信号）、0028（正确性裁判与卡片裁决字段）
