# 0026 — 迭代日志改为按「改动」累积

**What to build:** 迭代日志的编号语义从「第 N 轮对话」改为「第 N 次改动」，注入模型上下文的渲染文案同步改名，并新增核验结论字段。存量项目的旧结构条目在读取时兼容渲染，不因缺字段报错、不丢条目。这一步为下一张工单的「咨询轮不入账」铺路：咨询轮不入账后两种编号会错位，继续叫「第 N 轮」等于对模型说谎。原始用户诉求仍然完整落库——蒸馏版是模型写的、可能失真，原话才是权威数据。遵循 ADR 0005「迭代日志调整」段、CONTEXT.md「迭代日志」词条与规格 0021。

**Blocked by:** 0025（核验结论字段的内容来自自洽性核验）

**Status:** ready-for-agent

- [ ] 日志条目序号语义为「第 N 次改动」，注入模型上下文的渲染文案同步改名
- [ ] 条目新增核验结论字段；失配、越界、未完成的结论均入账（越界轮虽不留档快照，改动却留在磁盘上，必须留这条日志，否则后续轮次无从理解磁盘为什么是现在这个样子）
- [ ] 存量项目的旧结构条目（旧序号字段名、无核验结论字段）读取时兼容渲染，不报错、不丢条目
- [ ] 原始用户诉求完整落库，不因改用蒸馏版而丢失权威数据
- [ ] 暂不设截断或聚合上限（净 token 账持平或更短，不预先优化）
- [ ] 测试使用 fake 模型，覆盖新旧条目混合渲染、核验结论入账、以及日志注入后模型在后续轮次仍能读到早期改动
