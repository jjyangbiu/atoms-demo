# 03 — 工程师模式生成主链路（曳光弹）

**What to build:** 平台的心脏一刀打通：用户创建项目（默认工程师模式）、用一句话描述需求，工具调用智能体循环工作，文本与工具事件全量流式返回，生成的多个文件真实落盘。同一工单内含"可编程伪模型"测试基建——后续所有智能体相关测试复用它，任何测试不得调用真实 MiniMax API。

后端：项目表与创建接口；LangChain 工具调用智能体（read_file / write_file / edit_file 工具，系统提示写入"仅纯前端 + CDN、入口 index.html、禁构建"硬约束）；消息发送接口以 SSE 流式返回（事件：text / tool / done / error）；文件落盘带路径穿越防护与扩展名白名单；失败有限重试后以 error 收尾。前端：工作台项目列表、项目页左栏聊天流（Markdown 文本 + 工具事件时间线）、消息输入框、SSE 消费。

**Blocked by:** 02（工程脚手架 + 注册登录）

**Status:** done

- [x] 登录用户可创建项目并发送需求消息，SSE 流中依次出现 text 与 tool 事件、以 done 收尾（done 在持久化完成后发出，且是流的最后一个事件）
- [x] 生成结束后项目目录含至少 index.html 的多文件产物，文件内容即智能体工具调用的结果
- [x] 智能体失败/超时场景返回 error 事件，前端给出可重试的提示（错误横幅 + “重新生成”按钮）
- [x] 可编程伪模型基建就位：预排工具调用序列即可驱动完整生成流程的测试通过
- [x] MiniMax-M3 模型与 base_url 经环境变量配置，本地无 Key 时测试仍全绿
